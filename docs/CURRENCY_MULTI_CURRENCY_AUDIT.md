# تقرير تدقيق تعدد العملات (دينار / دولار)

**النطاق:** صحة البيانات والمنطق المحاسبي والأرصدة وتأثير العملة فقط (بدون واجهات/تصميم).  
**الوضع:** تحليل فقط — لا تعديل على الكود أو قاعدة البيانات في هذه المرحلة.  
**الأساس:** النظام كان يعمل بالدينار فقط ثم أُضيف دعم الدولار (`AccountingCurrency`: IQD=0, USD=1).

---

## الخلاصة التنفيذية

الهجرة نفسها **لا تغيّر مبالغ المستخدمين القدامى** (كل الصفوف القديمة صارت `Currency=IQD`, `FxRate=1`). الطبقة الأساسية للأرصدة (`CustomerBalanceHelper` / فلاتر التقارير / قواعد `EnsureSameCurrency`) مصممة لفصل العملتين.

لكن النظام **غير سليم محاسبياً بعد إضافة الدولار** بسبب أخطاء صامتة. أخطرها:

1. فساد عملة المستندات عبر المزامنة
2. حذف سندات FIFO بدون عكس التسديد على الفواتير
3. حذف فاتورة يخفي سندات دون عكس الصندوق
4. خلط مصروفات الدولار في أرباح المستثمرين

لا يوجد دفتر قيود مزدوج (`JournalEntry`)؛ المحاسبة وثائقية (فاتورة / سند / مصروف / تحويل) مع رصيد مخزّن على القاصة والبنك.

---

## ما هو آمن للبيانات القديمة

| عنصر | الحكم |
|------|--------|
| الهجرة `20260925210000_AddAccountingMultiCurrency` | آمنة: defaults `"IQD"` / `1` بدون لمس المبالغ |
| أرصدة القاصات/البنوك القديمة | تبقى دينار؛ عمود `Currency` ثابت لكل حساب |
| رصيد العميل/المورد المحسوب | يفترض IQD عند غياب الفلتر؛ البيانات القديمة IQD فقط |
| تغيير سعر الصرف اليومي | لا يعيد تقييم المستندات القديمة (يستخدم `FxRate` المخزّن) — **طالما لم يُعاد حفظ الفاتورة من الواجهة** |
| قواعد الإنشاء | ترفض ربط قاصة/سند/فاتورة بعملات مختلفة وترفض USD بـ FxRate ≤ 0 |
| تطبيق سندات الدين/الصرف FIFO | يفلتر بنفس عملة السند (`i.Currency == voucher.Currency`) |

## تقييم السيناريوهات

| # | السيناريو | الحكم |
|---|-----------|--------|
| 1 | قديم دينار فقط | **آمن غالباً** من الهجرة؛ يبقى عرضة لأخطاء الحذف FIFO/الفاتورة (ليست خاصة بالدولار) |
| 2 | قديم + دولار | الرصيد الدينار مستقل منطقياً في المساعدات؛ خطر الخلط عبر تقارير/مستثمر/مزامنة/أقساط |
| 3 | جديد دينار | يعمل كالسابق |
| 4 | جديد دولار | إنشاء محلي جيد؛ **المزامنة تفسد العملة** |
| 5 | دينار + دولار معاً | فصل في المساعدات؛ فجوات في الأقساط الجماعية والطباعة والإجماليات |
| 6 | أرصدة قديمة + عمليات دولار | لا يجب أن تتغير أرصدة الدينار إن لم تُحذف/تُزامن بشكل خاطئ؛ قاصات منفصلة مطلوبة |
| 7 | تغيير سعر الصرف بعد عمليات | جدول الأسعار لا يعيد التقييم؛ **التعديل من الواجهة قد يستبدل FxRate التاريخي** |

## أولوية الإصلاح المقترحة (مرحلة لاحقة)

1. إصلاح `SyncMapper` للفواتير/المصروفات/التحويلات + اختبار round-trip USD.
2. عكس تخصيص FIFO عند حذف السند؛ حذف فاتورة يعكس السندات نقدياً.
3. فلتر عملة لمصروفات أرباح المستثمرين.
4. `HasConversion<string>` في Cloud + تسوية القاصة بالعملة الصحيحة.
5. أقساط oldest-first / الأرصدة الافتتاحية / حماية FxRate عند التعديل / التحقق المحاسبي.
