# ربط الحاسبات الرئيسية والفرعية — نظام قيد

## نظرة عامة

يدعم نظام قيد أربعة أوضاع نشر:

| الوضع | الوصف |
|-------|--------|
| **مستقلة (Standalone)** | الوضع التقليدي — قاعدة بيانات LocalDB محلية (الافتراضي للعملاء الحاليين) |
| **رئيسية (MainServer)** | تخزين قاعدة البيانات واستقبال الحاسبات الفرعية عبر الشبكة |
| **فرعية (BranchClient)** | اتصال مباشر بقاعدة بيانات الحاسبة الرئيسية بدون مزامنة |
| **سيرفر مشترك (SharedServer)** | لصق Connection String لـ SQL Server على سيرفر — كل الحاسبات تتصل بنفس القاعدة |

## المتطلبات

### الحاسبة الرئيسية
- Windows 10/11
- SQL Server Express 2022 (أو أحدث) مع TCP/IP مفعّل
- المنفذ 1433 مفتوح في جدار الحماية
- نفس نوع النظام (محاسبة / فنادق / عقود / بيع وشراء) على الرئيسية والفرعية

### الحاسبة الفرعية
- Windows 10/11
- اتصال WiFi أو Ethernet بنفس الشبكة المحلية
- **لا تحتاج** LocalDB أو مجلد بيانات محلي

### السيرفر المشترك
- SQL Server (Express / Standard / على سيرفر أو سحابة) يمكن الوصول إليه من كل الحاسبات
- مستخدم SQL بصلاحيات على القاعدة
- المنفذ مفتوح (عادة 1433) وجدار الحماية يسمح بالاتصال
- على كل جهاز: نفس (أو مكافئ) Connection String في معالج الإعداد أو شاشة ربط الحاسبات

## التنصيب لأول مرة

1. شغّل التطبيق واختر **نوع النظام**
2. اختر **نوع الحاسبة**:
   - **رئيسية**: يُهيّئ SQL Express ويُنشئ رمز ربط للفروع
   - **فرعية**: يبحث على الشبكة عن الرئيسية أو أدخل IP يدوياً
   - **مستقلة**: يظهر خطوة اختيار سيرفر SQL المحلي
   - **سيرفر مشترك**: الصق Connection String واختبر الاتصال
3. للوضع المستقل: اختر اسم السيرفر من القائمة (LocalDB / Express / مثيلات مثبتة) واختبر الاتصال — يُحفظ في `appsettings.json`
4. للفرعية: أدخل بيانات SQL ورمز الربط واضغط **اختبار الاتصال**
5. للسيرفر المشترك: الصق السلسلة (مثال أدناه) → **اختبار الاتصال** → إنهاء

```
Server=192.168.1.10,1433;Database=AlMuhasibDb;User Id=sa;Password=YourPassword;TrustServerCertificate=True;MultipleActiveResultSets=True
```

> اسم قاعدة البيانات يُضبط تلقائياً حسب نوع النظام (محاسبة / فنادق / …). كرّر نفس الإعداد على كل الحاسبات.

## تعديل الربط لاحقاً

من القائمة: **ربط الحاسبات**

- **فرعية**: عدّل IP، المنفذ، المستخدم، كلمة المرور، رمز الربط — ثم احفظ وأعد تشغيل التطبيق
- **رئيسية**: فعّل/أوقف استقبال الفروع، جدّد رمز الربط، عدّل اسم الجهاز
- **سيرفر مشترك**: عدّل Connection String واختبر ثم احفظ وأعد التشغيل

## ملفات الإعداد

| الملف | المسار |
|-------|--------|
| نوع النظام والنشر | `%LocalAppData%\AlMuhasib\system-profile.json` |
| إعدادات الفرعية | `%LocalAppData%\AlMuhasib\network-connection.json` |
| إعدادات الرئيسية | `%LocalAppData%\AlMuhasib\main-server-settings.json` |
| سلسلة الاتصال (المستقلة/الرئيسية/السيرفر المشترك) | `{مجلد التثبيت}\appsettings.json` → `ConnectionStrings:DefaultConnection` |

## اكتشاف الشبكة

- بروتوكول UDP على المنفذ **40777**
- طلب: `QAYD_DISCOVER_v1`
- يعمل على WiFi و Ethernet في نفس الشبكة المحلية
- **لا يُستخدم** في وضع السيرفر المشترك (الاتصال مباشر عبر Connection String)

## قيود الحاسبة الفرعية

- لا تُطبّق migrations
- لا تُنشئ قاعدة بيانات محلية
- النسخ الاحتياطي والمزامنة السحابية معطّلان
- معالج الإعداد الأولي يُتخطى

## وضع السيرفر المشترك — ملاحظات

- كل جهاز يحفظ `DefaultConnection` محلياً ويتصل بالسيرفر مباشرة
- يُفضّل تشغيل جهاز واحد أولاً بعد التحديث لتطبيق ترحيلات القاعدة، ثم تشغيل الباقي
- لا حاجة لرمز ربط أو اكتشاف شبكة

## استكشاف الأخطاء

| المشكلة | الحل |
|---------|------|
| لا يظهر الجهاز الرئيسي | تأكد من تفعيل «السماح للفروع» و«الاكتشاف» على الرئيسية |
| فشل الاتصال (53) | تحقق من IP، الشبكة، وجدار الحماية على الرئيسية |
| فشل تسجيل الدخول (18456) | تحقق من مستخدم SQL وكلمة المرور ورمز الربط |
| قاعدة البيانات غير موجودة (4060) | شغّل التطبيق على الرئيسية أولاً لإنشاء القاعدة |
| فشل اتصال السيرفر المشترك | تحقق من سلسلة الاتصال، TCP/IP، وجدار الحماية على سيرفر SQL |

## سكربت تهيئة SQL Express

```powershell
.\scripts\configure-sql-express.ps1 -DatabaseName AlMuhasibDb -BranchUsername QaydBranchUser -BranchPassword "YourPassword"
```

> يتطلب صلاحيات مسؤول

## التوافق مع العملاء الحاليين
