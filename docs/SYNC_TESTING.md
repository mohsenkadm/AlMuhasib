# اختبار المزامنة السحابية — AlMuhasib

## المتطلبات

- تشغيل `AlMuhasib.Api` محلياً (`http://localhost:5265`)
- حساب تجريبي: `demo` / `demo123`
- تطبيق WPF مع إعدادات المزامنة السحابية

## سيناريوهات الاختبار

### 1. مزامنة كاملة (Push + Pull)

1. أنشئ عميلاً، مخزناً، منتجاً، وفاتورة مبيعات.
2. من **المزامنة السحابية** → **مزامنة الآن**.
3. تحقق عبر Swagger: `GET /api/master-data/customers` و `GET /api/invoices`.

**النتيجة المتوقعة:** `IsSuccess = true`، رسالة «تمت المزامنة — N سجل».

### 2. الحذف الناعم (Tombstones)

1. احذف منتجاً أو عميلاً من النظام المحلي.
2. نفّذ المزامنة.
3. تحقق من السحابة أن السجل `IsDeleted = true`.

**النتيجة المتوقعة:** الحذف يظهر على السحابة بعد Push.

### 3. تعارض الرفع (LastPushedAt)

1. عدّل سجلاً على السحابة يدوياً بـ `UpdatedAt` أحدث.
2. عدّل نفس السجل محلياً بتاريخ أقدم.
3. نفّذ المزامنة.

**النتيجة المتوقعة:**

- `ConflictCount > 0`
- `IsSuccess = false`
- `LastPushedAt` **لا يتقدم** — إعادة المزامنة تعيد إرسال السجل المتعارض.

### 4. مزامنة تزايدية

1. نفّذ مزامنة ناجحة.
2. بدون تغييرات، نفّذ مزامنة ثانية.

**النتيجة المتوقعة:** bundle صغير أو فارغ، اكتمال سريع.

### 5. مرفقات العملاء

1. أرفق ملفاً لعميل محلي.
2. نفّذ المزامنة.

**النتيجة المتوقعة:** المرفق يصل للسحابة مع `FileData`.

### 6. فشل Pull (Rollback)

1. أوقف API أثناء Pull أو أفسد JWT مؤقتاً.
2. تحقق أن البيانات المحلية لم تتغير جزئياً (`LastPulledAt` لم يتقدم).

## ملاحظات ما بعد الإصلاح

- `SyncId` الفارغ يُصلَح تلقائياً عبر `SyncIdEnsurer` وترحيل `BackfillEmptySyncIds`.
- Pull يحترم النسخة المحلية الأحدث عند `UpdatedAt` أحدث من السحابة.
- المزامنة التلقائية محمية بـ `SemaphoreSlim` ضد التداخل.
